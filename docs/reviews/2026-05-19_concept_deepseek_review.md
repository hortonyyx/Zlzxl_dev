## 原始审阅输出

### 一、严重问题

**1. 合规与隐私风险未提及。** 课堂录音涉及教师、其他学生的声纹等个人信息,
无授权机制下长录音并上传、转写、存储,违反《个人信息保护法》及微信小程序
规范。MVP 无用户协议、隐私弹窗、教师授权设计。这是"是否可做"的前提。
建议增加合规方案(仅限个人学习使用 / 引导口头同意 / 本地处理),
或重新考虑场景。

**2. "语音优先"定位与 MVP 交互形态矛盾。** MVP 唯一与语音相关的是录音 +
转写,课后交互全是图文,无语音输入输出,也无用户主动与 AI 对话的通道。
产品沦为自动笔记 + 出题工具,与"学伴"定位不符。建议明确 MVP 的"语音优先"
是交互还是输入,或在 MVP 加基于脉络的语音问答。

**3. 学习脉络"逐课重写"的可行性与一致性矛盾。** 三个问题:上下文窗口与
成本(重写需塞入全部历史,超出限制、token 大、延迟高);内容抖动导致用户
失向(结构每次可能改变,与"固化场景"冲突);历史信号对齐崩溃(知识点被
重新拆分/合并,信号映射出错)。必须给出预算、范围控制机制、模型策略。

**4. 信号回写缺少知识点锚定方案。** 知识目标由 AI 动态提取,无稳定 ID 或
受控词表,不同课次会同义不同名、粒度不一,信号无法聚合。摧毁算法层和
状态色基础。建议设计知识点归一化机制(向量相似度合并 / 人工连接)。

**5. MVP 含不可控技术高风险点,无备选方案。** 小程序长录音 + 转写:录音
时长限制(45 分钟以上基本不可行,iOS 可能因内存被杀);进后台录音会中断
(后台音频权限只能用于播放);长音频转写时延、文件过大上传易失败。
文档承认风险但无降级方案(分段录音 + 本地分段转写 / 图文笔记替代等)。

### 二、值得商榷的点

**1. "冷启动首次价值"过于单薄。** 价值完全依赖 AI 输出质量,首堂课转写
错误/总结不准则无其他钩子。无新手引导、示例库、未上课时的体验内容。
建议预置 demo 库或引导式首课。

**2. 状态色定义含混。** "黄 = 有疑问 / 留存下滑 / 没测过"把三种不同性质
状态混为一谈,行动导向不同;"没测过"算灰还是黄边界模糊;简单规则可能
频繁跳变。

**3. eager 固化可能固化错误,无修正机制。** AI 生成内容可能出错,用户无
编辑/反馈入口,错误累积、信任崩塌;"记忆证据强可见"反而放大错误。

**4. 双视图新旧内容一致性问题。** 节点 append-only 而脉络不断重写,查阅
旧节点时其总结与当前脉络可能不一致,未说明"过时"标记。

**5. 只做"上课模式"是否真符合最小可行?** 上课模式频率低(一周几节)、
测试周期长、忘录则无价值;学习模式 / 自建节点更频繁。也许应先自建节点 +
手动输入跑通脉络与信号闭环,再补录音。

### 三、建议补充

1. 补一份端到端用户故事(打开 → 新建课程 → 录音 → 下课 → 总结 → 脉络 →
   测验 → 状态变化),暴露交互空白。
2. 明确知识目标的生命周期和归一化策略。
3. 给出学习脉络重写的技术约束(全量重写上限、知识点 ID 不变、模型选择)。
4. 补错误处理和人工干预开关(纠错回路)。
5. 补空 / 加载 / 失败状态描述。
6. 把"你的状态信号源"从问句改成明确格式定义。
7. 修正矛盾表述:明确模块触发权在谁、"学伴"的准确定义。

## Opus 对审阅的回应(校准)

- 严重 1(合规):同意是前提级,但严重度下调一档——标准解法成熟(个人
  用途定位 + 授权 + 本地优先),不致命。已定口径为个人用途。
- 严重 3 + 4(重写 / 锚定):同意,是最深的洞,合并为知识点稳定 ID 方案。
- 商榷 5(改做学习模式):不采纳反转——学习模式缺触发器正是要治的病;
  保留上课模式,但加"课后补录"缓解"忘录 = 零价值"。
- 其余按处置摘要分流。
