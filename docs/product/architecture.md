# 产品架构图

## 文档定位

本文是 Zlzl 的**产品 / 信息架构**图,描述库、知识库、脉络、节点、模块、
信号之间的结构与数据流。

不是部署 / 技术拓扑(ASR 选型、是否需要后端等仍待定,见
[concept.md](concept.md) 第 12 节)。完整设计理由见 [concept.md](concept.md)。

---

## 1. 信息架构总览

用户拥有多个库;每个库是一条学习路径,内部分知识库与节点流。

```mermaid
graph TD
  U["用户"] --> K1["库 · 设计史"]
  U --> K2["库 · 考研政治"]
  U --> Kn["库 · …"]
  K1 --> KB["知识库"]
  K1 --> NS["节点流"]
  KB --> RC["原始语料<br/>录音 / 转写 / 课件"]
  KB --> ML["学习脉络<br/>AI 维护 · 逐课迭代<br/>(库的主视图)"]
  NS --> N1["节点 = 一次会话<br/>append-only"]
  N1 --> MOD["模块<br/>总结 / 测验 / 闪卡 / 抽背 / 听写"]
```

要点:节点是**生产单元**,导航靠学习脉络,不靠浏览节点。

---

## 2. 双视图与信号闭环

写入路径(活动轴)与读取路径(内容轴)是同一份数据的两个视图。
模块运行产出掌握信号,经算法层得到掌握状态,回流脉络。

```mermaid
graph LR
  SESS["一次会话<br/>上课 / 学习 / 规划"] --> NODE["节点<br/>append-only 日志"]
  NODE --> CORPUS["原始语料"]
  CORPUS --> AISYN["AI 合成 / 重写"]
  AISYN --> ML["学习脉络<br/>读取 · 导航视图"]
  MOD["模块运行<br/>人驱动 or AI 驱动"] --> SIG["掌握信号<br/>按知识点的时间序列"]
  SIG --> ALGO["算法层<br/>间隔重复 / 遗忘曲线"]
  ALGO --> STATE["掌握状态<br/>绿 / 黄 / 灰"]
  STATE --> ML
  ML -. "导航 / 触发" .-> MOD
```

要点:回写**与驱动方无关**;固化的只有信号,不是题目。

## 3. 分层职责:算法层 vs AI 层

```mermaid
graph TD
  subgraph AILAYER["AI 层 — 管「懂没懂 / 学什么」"]
    A1["理解诊断<br/>识别概念误区"]
    A2["节点编排<br/>排哪些模块"]
    A3["内容生成 / 判开放式答案"]
  end
  subgraph ALGLAYER["算法层 — 管「记没记住」"]
    B1["间隔重复调度"]
    B2["遗忘曲线 / 留存度"]
  end
  AILAYER --> ALGLAYER
  ALGLAYER --> ST["掌握状态色"]
```

要点:AI 不做记忆调度;算法不做理解诊断。MVP 只用简单状态规则,
算法层(FSRS / SM-2)是 v2。

## 4. 上课模式 MVP 主线流程

```mermaid
flowchart TD
  A["课前<br/>进库 → 上课模式 → 开始录音"] --> B["课中<br/>转写 · 标记疑问 · 上传课件"]
  B --> C["下课 · 停止录音"]
  C --> D["AI 处理<br/>转写全文 → 提炼知识点"]
  D --> E["课堂总结 · 立即固化<br/>完整总结 + 要点提炼 + 核心问题"]
  E --> F["课后测验模块<br/>核心问题作答评分"]
  F --> G["回写掌握信号"]
  E --> H["重写学习脉络"]
  G --> H
  H --> I["用户回看<br/>脉络长大 + delta"]
```

要点:`核心问题`(陈述)与`测验`(作答)是同一内容的两个激活层;
课堂总结 eager 固化,测验信号回写后驱动脉络重写。

## 5. 数据实体关系(MVP 视角)

```mermaid
erDiagram
  库 ||--|| 知识库 : 含
  库 ||--o{ 节点 : 含
  知识库 ||--o{ 原始语料 : 存
  知识库 ||--|| 学习脉络 : 维护
  节点 ||--o{ 模块运行 : 包含
  模块运行 ||--o{ 掌握信号 : 产出
  掌握信号 }o--|| 知识点 : 关于
  学习脉络 ||--o{ 知识点 : 组织
```

要点:`掌握信号` 以"按知识点的时间序列"存储,是 v2 接入 SRS 算法
的基础,MVP 阶段即按此结构落库,避免后续迁移。
