陪伴型(账号级 · 有状态 · 随使用累积) ≠ 工具型(会话级 · 无状态 · 按功能调用)
1核心:两大体系
知识体系
WHAT · 学的"东西"
载体 = 知识点池。由输入喂养、由 AI 组织。稳定、可累积。
知识点 = 一等实体 稳定 ID 双链(图结构)
状态体系
WHEN / WHETHER · 掌握得怎样
载体 = 掌握信号 + 状态色。由学习 / 复习的回写驱动。动态、因人而异。
信号时间序列 绿 / 黄 / 灰 算法 + AI
学习脉络 = 两大体系叠加后的「读取视图 / 叙述层」
它不是第三个体系;用户永远看脉络(叙述),不看原始结构
2容器:库 = 一条学习路径
库 (如"设计史";实例可以是一门课,也可以是一个学习目标)
知识库
原始语料 · 录音 / 转写 / 上传资料 知识点池 · 知识体系的载体 学习脉络 · 库的主视图
节点流
节点 = 一次会话 · class 上课 / study 学习 append-only · 退到「历史」
节点是生产单元,不是导航单元——导航靠脉络。

算法层 — 管"记没记住"
间隔重复 / 遗忘曲线。把"状态"算成"到期清单"。确定性,不交给 LLM。
AI 层 — 管"懂没懂 / 学什么"
诊断概念误区、连暗线、把到期清单编排成一个学习节点。
4模块 = 知识点的"输出模式"
学习功能封装成模块,永远绑定一个知识目标(不做 app 级功能瓷砖)。 由 AI + 人编排进节点;每个模块跑完回写掌握信号 → 喂养状态体系。

5三大模式与 MVP 范围
上课模式 MVP
课堂录音 → 课后整理。知识点的输入泵。
学习模式 MVP
到期清单 → AI 编排复习。知识点的复习循环 = 护城河。
规划模式 v2
按显式目标 + 时间表编排未来一串学习节点。复习循环的长线延伸。
MVP 验证:钩子(上完课立即有好总结) + 护城河(脉络可见地长大、跨课记忆、复习循环转起来)
