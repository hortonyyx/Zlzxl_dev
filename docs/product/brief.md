# 产品简报

> 一页纸摘要。详细事实来源见 [concept.md](concept.md)。

## 产品定位

Zlzl 是一款**语音优先的长周期 AI 学伴**,目标是成为陪伴式的 AI 辅导老师,
而非工具型 AI 产品(区别于小猿、豆包爱学)。

目标用户:**大学生**;首批锁定**概念密集、叙述型、考试重理解与论述的
大学课程**(设计史、历史、文科理论)。后续再考虑转型类考试、强练习课型、K12。

## 要解决的问题

AI 已足够强,但用户:

1. 对 AI 的能力和适用场景认知不清。
2. 缺少一个**固化的学习场景**——临时开的 AI 对话往往不了了之。

Zlzl 用结构化的"库 + 脉络 + 节点"体系,把零散的 AI 使用沉淀成可累积的长期学习。

## 设计原则

- 强 AI 编排:只搭输入输出架构,学习路径交给 AI,不做功能工具箱。
- 少选择:给用户的选择越少越好(参考多邻国)。
- 界面简洁、干净、易用。
- 记忆机制不可见,记忆证据强可见——这是留存关键。

## 产品结构

- **库** = 一条学习路径(如"设计史")。
- 库内分**两大体系**:知识体系(知识点池,WHAT)+ 状态体系(掌握信号与
  状态,WHEN/WHETHER);**学习脉络**是二者叠加的读取视图,是库的主视图。
- **节点** = 一次会话(`class` 上课 / `study` 学习),append-only,作"历史";
  节点是生产单元,导航靠脉络。
- 学习功能封装为**模块**(总结/测验/闪卡/抽背/听写…),由 AI 编排进节点;
  模块统一向状态体系回写掌握信号。
- 三大模式:上课 / 学习 / 规划。

## MVP 范围

MVP 做**上课模式 + 学习模式**两个模式——它们是同一个循环的两半:

- **上课线**:多模态输入 → 课后三段式课堂总结(固化)→ 知识点入池 →
  脉络迭代。
- **学习线**:进库 → 算法出到期清单 → AI 编排学习节点(测验 / 闪卡)→
  复习回写信号 → 状态与脉络更新。

验证策略:先用 mock 工程跑通体验闭环,验证产品价值,再硬化录音 / ASR /
云流水线。

## MVP 验证什么

- 获客钩子:上完课立即拿到比自己记的更好的课堂总结。
- 护城河:随课次增长、可见的学习脉络、跨课记忆、转得起来的复习循环。

验收核心锚定**记忆证据**(delta、学伴便签、跨课关联),而非总结质量。

## 暂不做(v2)

- 规划模式(显式目标 + 时间表的多节点规划)。
- 完整 SRS / 遗忘曲线调度(MVP 用简单到期规则,数据按信号时间序存储)。
- 测验 / 闪卡以外的模块(语音抽背、听写)。
- 知识点带类型双链与图感知编排。
- 用户在脉络上主动触发模块的入口;测验语音作答。
- 语音轻输出;强练习课型;K12;跨平台框架。
