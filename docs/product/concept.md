# 产品概念与设计说明

## 文档定位

本文是 Zlzl 产品概念的**详细事实来源**。`brief.md` 是它的一页纸摘要。
它记录"决定了什么"和"为什么这样决定"——决策背后的张力与权衡，
是切换模型时最容易丢失、也最需要保留的信息。

本文已纳入 2026-05-19 DeepSeek、Codex 两轮交叉审阅的结论与处置，见第 13 节。

---

## 1. 产品定位与背景

Zlzl 是一款语音优先的长周期 AI 学伴，定位陪伴式 AI 辅导老师。

差异化：市面 AI 学习产品（小猿、豆包爱学）是**工具型**——会话级、无状态、
按功能调用。Zlzl 是**陪伴型**——账号级、有状态、随使用累积。

> 注：本文"学伴"指**无间断、结构化、有记忆的学习陪伴**，不等于"实时对话
> 伙伴"。"语音优先"是产品的长期形态；MVP 阶段语音以输入侧为主（见第 13 节）。

**目标用户与课型**：MVP 聚焦**大学生**，且首批锁定**概念密集、叙述型、
考试以理解与论述为主的大学课程**（如设计史、历史、文科理论课）。数学 /
编程 / 物理等强练习型课程不进首批——课堂总结 + 开放题评分对它们撑不住。
后续再考虑转型类考试（考研 / 考公 / 考证）、强练习课型、K12。

背景判断：

- AI 已足够强，做"AI 套皮"没意义。
- 但存在两个问题，使"成熟伴学体系"成为合理需求：
  1. 多数人对 AI 能力边界和适用场景认知不清。
  2. 学习需要一个**固化的场景**。临时开的 AI 对话缺少结构，常常不了了之。

---

## 2. 要解决的问题（及它对设计的约束）

核心要验证的假设**不是**"伴学架构是否被需要"（这难以被 MVP 证伪），
而是更具体、更危险的那个：

> 结构化的陪伴能否带来复用与留存，而裸用通用大模型不能。

两个推论约束了所有设计：

- 陪伴价值是**纵向累积**的——用了 N 次才显现。于是有冷启动陷阱：
  **第一次使用必须单次就有价值**，否则用户不会回来兑现累积价值。
- 因此 MVP 必须同时给出"获客钩子"（单次价值）和"护城河"（跨次累积），
  缺一不可。

---

## 3. 设计原则

- **强 AI 编排**：产品只搭输入输出架构，把学习路径的编排交给 AI。
  不做功能工具箱（不把一堆功能瓷砖丢给用户自己选）。
- **少选择**：给用户的选择越少越好（参考多邻国）。
- **可见 ≠ 可选**：可以让用户*看到* AI 排好的路径（给"抓手"），
  但不让用户自由配置（守住"少选择"）。多邻国正是如此。
- **界面简洁、干净、易用。**
- **记忆机制不可见，记忆证据强可见。** 用户不该去"管理"一个记忆库；
  但 AI 必须不断*展示*它记得你——这是陪伴感和留存的关键。

## 4. 核心架构

### 4.1 两大体系：知识体系 与 状态体系

整个产品的数据可分成两大体系，二者作用层不同：

- **知识体系**——学的"东西"。由输入*喂养*（录音 / 上传资料）、由 AI
  *组织*。载体是知识点池（4.4）；它回答 **WHAT**。稳定、可累积、跨用户
  结构相似。
- **状态体系**——这个用户掌握得怎样。由学习 / 复习的回写驱动。载体是
  掌握信号与知识点状态（第 6、7 节）；它回答 **WHEN / WHETHER**。
  动态、因人而异。

学习脉络（第 5 节）**不是第三个体系**，它是这两个体系叠加后的
**读取视图 / 叙述层**。

这个二分解释了为什么"算法管记忆调度、AI 管理解编排"能成立——算法主要
作用在状态体系，AI 主要作用在知识体系的组织与输出编排。

### 4.2 库

`库 = 一条学习路径`。实例可以是一门课（"设计史"），也可以是跨课的目标。
上课模式下，自然实例是一门课。

### 4.3 知识库

库内的知识沉淀，含三部分：

- **原始语料**：上课录音、转写、用户上传的课件 / 图片 / 资料。
- **知识点池**：库内所有知识点的集合，是知识体系的具体载体（见 4.4）。
- **学习脉络**：对知识点池 + 状态的 AI 维护、逐课迭代的呈现视图（见第 5 节）。

### 4.4 知识点：一等实体、稳定 ID、双链

知识点是**一等实体，拥有稳定 ID**，是掌握信号的锚点：

- 掌握信号挂在知识点上。若知识点没有稳定 ID，不同课次 AI 会提取出
  "同义不同名、粒度不一"的知识点，信号无法聚合，算法层和状态色的地基
  就塌了。
- 知识点池是**受管的**：AI 每次提取候选知识点后，先与池内已有知识点做
  **归一化匹配**——语义命中则复用已有 ID；确为新知识点才分配新 ID。
- 知识点 ID 一经分配不变。脉络"重写"只重排叙述，**绝不改动知识点 ID**。

**知识点之间是图，不是表。** 知识点存在关系（前置 / 对比 / 延伸 / 举例），
本文说的"连暗线"本质就是在生成这些链接。所以知识体系的数据形态是一张
**AI 维护的知识图谱**（节点 = 知识点，边 = AI 发现的关系）。

- 关键区别：链接由 **AI 维护**，不是用户手建。给用户一个 Obsidian 式图谱
  去编辑，会违反"少选择 / 用户不维护知识体系 / 记忆机制不可见"。
  用户永远看脉络（叙述），不看图谱（原始结构）。
- 落地节奏：**MVP** 知识点只带轻量 `relatedIds`；带类型的链接 + 图感知的
  复习编排是"做大"版本（v2+）。

### 4.5 节点

`节点 = 一次会话`。每次使用新建一个节点。节点流是 append-only 的。
节点有类型：`class`（上课）/ `study`（学习）——模式无关的通用单元。

关键定位：**节点是"生产单元"，不是"导航单元"。** 用户不靠浏览节点找
知识，只靠脉络导航。节点流退到「历史」，次要。

### 4.6 双视图：为什么节点不能当导航

学习有两条轴：

- **内容轴**：学的"东西"。其载体是知识点池（4.4）。稳定、结构化。
- **活动轴**：你"做过"什么、什么时候做的。流式、时间序。

人找学习内容靠内容轴（"我要复习透视"），几乎不会靠活动轴。节点流是
活动轴。若让节点流承担导航，就等于"按日期组织的笔记本"——用户会失去
对学习的掌控感。

解法是**同一份数据的两个视图**：

- 节点流 = **写入模型**：append-only 会话日志。认知负担低。
- 学习脉络 = **读取模型**：AI 合成、AI 维护的知识结构。掌控感来自这里。

用户不再需要亲手*搭建和维护*知识结构，但仍需要*按它导航*——只是从
"用户手画"变成"AI 自动画"。

## 5. 学习脉络

### 5.1 是什么

- 一个库一份，是库的主视图。
- **学习脉络是知识点池 + 状态的"读取视图"**：它把知识点组织成可导航的
  叙述，但不持有知识点的身份——ID 在知识点池里。
- 每次课后 AI **重写脉络的叙述**（不是追加），但**知识点 ID 与历史信号
  不受影响**。重写的是"怎么讲"，不是"知识点是什么"。
- 固定几个版块，内容在版块内流动。
- **学伴视角**，不是百科视角：写"这门课走到哪 + 你在哪"。

### 5.2 不是什么

不是知识树形工具，不是全知百科，也不是给用户编辑的图谱。它要有陪伴感
——体现为关于"你"的内容，而非关于"知识"的内容。

### 5.3 三层呈现（解决"文档模式太粗糙"）

模型是一份迭代产物，但**渲染**成三层，避免一面文字墙：

- **第 1 层（打开即见）**：竖向生长的「学习路径」，每次课 = 路径一站，
  带状态点（绿 / 黄 / 灰）。顶部一句学伴口吻的「本次更新」。
  旁边浮「学伴便签」卡片（还没解决的 / 我观察到的）。
- **第 2 层（点某一站）**：那节课的知识提炼 + 你的状态。
- **第 3 层**：完整文档 / 转写 / 节点。

库的"脸"是一条会长的路径。

### 5.4 delta 是吸引力的来源

每次课后进来，先看到的是"**变化**"——路径长了一站、黄点转绿、发现新暗线。
变化可见，静态文档就活了。几乎零成本，优先做。

### 5.5 版块（示意）

- 课程走到哪了
- 知识脉络（逐课）
- 还没解决的
- 我观察到的

后三块是关于*你*的，是陪伴感和记忆感知的来源。去掉它们，脉络就退成
普通课程大纲。

## 6. 学习功能模块

### 6.1 统一模型

学习功能封装为**模块**。一个模块 =

- 输入：一个知识目标 / 一段语料切片。
- 交互形态：翻闪卡 / 答题 / 语音抽背 / 听写……
- 产出：给用户的学习内容。
- **回写脉络的掌握信号**。

最后一条是模块与脉络的咬合点：**没有它，模块只是工具箱瓷砖；有了它，
模块是状态体系的"感觉器官"**——靠模块感知你掌握得怎样。

### 6.2 模块永远绑定知识目标

工具箱之所以是反模式，是因为瓷砖是"功能"（抽象的手段）。用户要的不是
"一个测验"，而是"搞定透视那道题"。所以模块永远挂在一个知识目标上，
不做 app 级功能瓷砖。

### 6.3 驱动：人与 AI 都保留

- **AI 驱动**：AI 编排节点时自动放入模块。
- **人驱动**：用户在脉络的某个知识点上主动触发（"测一测"）。

回写**与驱动方无关**：信号记录锚点是知识点 ID（经 4.4 归一化保证稳定），
谁触发只是元数据。状态是**每个知识点的信号时间序列**——长周期管理需要
练习历史。

### 6.4 模块目录

| 模块 | 交互形态 | 回写信号 | MVP |
|---|---|---|---|
| 知识点 / 课堂总结 | 阅读（被动） | 无，在输入侧 | ✓ |
| 测验 | 答题判对错 | 每个知识点 对 / 错 | ✓ |
| 闪卡 | 翻卡 + 自评 | 每张卡记忆强度 | ✓ |
| 语音抽背 | AI 出声问、口头答、AI 评 | 每点口述掌握度 | v2 |
| 听写 | AI 念、用户写 | 术语准确率 | v2 |

## 7. 长周期学习管理：状态、算法与规划

### 7.1 算法层 vs AI 层

学习状态的维护不是"算法 or AI"二选一，二者在不同层：

- **算法层**管"**记没记住**"：间隔重复 / 遗忘曲线（FSRS、SM-2 类）。
  确定性、便宜。**不交给 LLM**——LLM 做一致的数值状态跟踪很差。
  算法层在「按知识点 ID 的信号时间序列」上运行。
- **AI 层**管"**懂没懂**"与"**接下来学什么**"：诊断概念误区、连暗线、
  编排节点、判开放式答案。

一句话：**算法管记忆调度，AI 管理解诊断与路径编排。AI 不做记忆调度。**

### 7.2 状态色

- 绿 = 算法判定留存度高 **且** 无未解疑问。
- 黄 = 有疑问悬着 / 留存度下滑 / 没测过 之一。
- 灰 = 未涉及。

状态转移是**信号驱动**，不是数节点。具体的信号字段、状态转移与站点
汇总规则在 design.md 落地。

### 7.3 从状态到规划：长期循环

绿黄灰是"地图"（现在在哪），不是"计划"（接下来做什么）。从地图到计划
两步，这两步就是"AI 介入规划"的全部：

1. **算法层把"状态"变成"到期"**：绿不是永久的，遗忘曲线说绿点 N 天不碰
   会重新到期。算法层看每个知识点的信号时间序列，算出**今日到期清单**
   ——黄点立即到期、绿点按间隔到期、灰点不计。
2. **AI 层把"到期清单"编排成"一个学习节点"**：从清单里挑 + 排 + 配模块，
   给用户一个有抓手的学习节点（"给你排了 5 个点，约 20 分钟"）。

算法管"何时该复习什么"（客观），AI 管"今天这节学什么、怎么学"（判断）。

这个循环发生在**学习模式**里：进库 → 算法出到期清单 → AI 编排学习节点
→ 复习 → 新信号回写 → 算法更新到期。**这个循环就是产品的护城河**
（复利留存）。上课模式只"灌"知识点、不"复习"，单独跑这个循环不存在。

> MVP 算法用**简单到期规则**（黄即时到期 / 绿固定 N 天间隔 / 灰不计），
> 完整遗忘曲线 FSRS 留 v2。循环用粗糙间隔也转得起来；FSRS 只是后来把
> 间隔变聪明。规划模式（显式目标 + 时间表的多节点规划）是此循环的长线
> 延伸，留 v2。

## 8. 产物固化策略：eager vs lazy

按"记录 vs 练习"切：

- **记录类**（完整总结 / 要点 / 核心问题 / 脉络更新）：每课后**立即固化**。
  它们是事实记录，也是让脉络变"活"的 delta。
- **练习类**（测验 / 闪卡 / 抽背）：**按需生成，不固化题目**。一份两周后
  的练习应针对这期间忘掉的东西。
- **固化的只有信号**，不是题目。模块永远能对着当前掌握状态重新生成。
- **固化 ≠ 不可纠错**：记录类产物虽立即固化，仍需提供轻量纠错入口
  （用户标记"这里不对"）。纯 AI 生成必须有纠错回路。纠错本身也是信号。

## 9. 三大模式

- **上课模式（MVP）**：课堂录音 → 课后转写、生成三段式课堂总结、知识点
  入池、更新脉络。是知识点的**输入泵**。
- **学习模式（MVP）**：进库后由算法 + AI 编排学习节点，在其中按到期清单
  复习，信号回写。是知识点的**复习循环**。
- **规划模式（v2）**：AI 按显式目标（交互式定义目标、时间）编排未来一串
  学习节点与时间表。是学习模式循环的长线延伸。

模式间用节点（`class` / `study`）作为通用单元串联。

> 注：`库` 在新建时分**课程学习 / 自主学习**两类，选定后决定主要输入方式。
> MVP 专注课程学习库。纯自主学习库的交互——尤其学习节点"完全由 AI 安排"
> 是否适合自学场景——需单独重新设计，留待后续讨论（已标记）。

## 10. 关键设计张力（显式记录，供后续模型理解）

- **动态编排 vs 固化场景**：AI 临时编排的节点也是会话，也可能"不了了之"。
  固化感必须来自*库结构 + 节点这个仪式 + 记忆系统*，而非节点内的模块编排。
- **强 AI vs 抓手**：纯空白对话框作主交互会重造"空白聊天 → 不了了之"。
  解法：节点带着排好的结构打开，对话是节点内的执行层。
- **转写是钩子，不是护城河**：语音转写是被验证的强需求，但元宝 / 讯飞
  已占住"转写"这个 job，差异化在转写*之后*的知识沉淀与跨课记忆。
- **脉络可重写 vs 知识点须稳定**：脉络的*叙述*可逐课重写，但知识点的
  *身份*（ID）必须稳定。解法是把"叙述"与"身份"分离——身份在知识点池，
  叙述在脉络。
- **产品面大 vs 工程风险大**：这是两个独立的轴。MVP 含双模式（产品面），
  但工程风险（长录音 / ASR / 云流水线）先 mock，见 §11.3。

## 11. MVP 范围与理由

### 11.1 MVP = 上课模式 + 学习模式

MVP 包含两个模式，因为它们是**同一个循环的两半**，拆开各自都不完整：

- 上课模式 = 知识点的**输入泵**（把课堂内容灌进知识体系）。
- 学习模式 = 知识点的**复习循环**（到期 → 编排 → 复习 → 回写）。

上课模式自带课表触发器、是专有数据入口；但它只能验证"钩子"（单次价值）。
"护城河"（复利留存）是学习模式里的复习循环——所以要验证核心假设，
两个模式都得在。规划模式留 v2。

### 11.2 MVP 主线

- **上课线**：多模态输入 → 课后课堂总结（三段式，立即固化）→ 知识点入池
  与归一化 → 脉络迭代。
- **学习线**：进库 → 算法出到期清单 → AI 编排学习节点（测验 / 闪卡）→
  复习回写信号 → 状态更新 → 脉络 delta。
- **共享**：知识点池、掌握信号、学习脉络、模块。

### 11.3 验证策略：先 mock 工程，跑通体验闭环

"大"有两个轴——产品面（模式）和工程风险（长录音 / ASR / 云流水线）。
MVP 先把**完整产品循环跑在 mock 的工程上**：录音 / ASR 用手动文本输入
代替，云流水线人工触发或 mock。先用真人感受"总结 → 脉络 delta → 测验 →
状态 → 复习 → 跨课记忆"是否有价值；再硬化工程。这样不会做很久才发现
体验不成立。tasks.md 的阶段 0 即为此最薄体验闭环。

### 11.4 MVP 验证什么

- **钩子**：上完课立即拿到比自己记的更好的课堂总结。
- **护城河**：脉络可见地长大、跨课记忆、复习循环转得起来。

**核心验收锚定"记忆证据"而非"总结质量"**：本次更新 delta、学伴便签、
跨课关联、用户多次后仍主动回库——这些弱了，产品就退化成"自动笔记 +
出题"。产品验证指标（留存 / 复访 / 测验完成率 / 纠错率）见 requirements.md。

### 11.5 v2（暂不做）

规划模式、完整 SRS / FSRS、知识点带类型双链与图感知编排、测验 / 闪卡
以外的模块（抽背 / 听写）、用户在脉络上主动触发模块的入口、语音轻输出、
强练习课型、K12、跨平台框架。
