## 目标

第一版 MVP 要先验证一个完整体验闭环:

```text
新建课程学习库 → 输入一节课内容 → 生成课堂总结 → 知识点入池 →
学习脉络出现 delta → AI 编排今日学习 → 测验 / 闪卡 → 掌握信号回写 →
状态色和脉络更新
```

首要目标不是立刻把录音 / ASR / 云流水线全部做真,而是尽快用真实小程序 UI
+ mock 服务跑通"记忆证据"是否成立。若体验不成立,停止工程硬化,回到产品
和原型迭代。

## MVP 范围

包含:

- 微信原生小程序 + TypeScript。
- 课程学习库:库列表、新建库、空库冷启动、demo 示例库。
- 库主页:学习脉络、今日学习、本次更新、学伴便签。
- 上课线 mock:手动输入课堂内容,产出三段式总结、知识点、脉络 delta。
- 学习线 mock:到期清单、AI 编排学习节点、测验、闪卡、节点结果。
- 共享领域模型:Library、KnowledgePoint、MasterySignal、Node、Mailuo。
- 服务层接口 + mock 开关,后续可切微信云开发。
- 每个阶段完成后的检查、微信开发者工具验证和跨模型审阅。

暂不包含:

- 规划模式。
- 完整 SRS / FSRS。
- 自主学习库完整体验。
- 语音抽背、听写、语音轻输出。
- 知识点带类型图边和图感知编排。
- 上线级合规、删除数据入口、账号体系。
- MVP 验证前的 Taro / uni-app / React / Vue 等跨端框架。

## 第一版成功标准

功能成功:

- [ ] 可在微信开发者工具打开项目,并走通所有 MVP 主路径页面。
- [ ] mock 数据下可完成至少两节课的循环,第二节课能显示跨课关联。
- [ ] 知识点 ID 在多次课之间稳定,掌握信号按知识点记录。
- [ ] 今日学习不是静态按钮,能由状态 / 到期项生成可解释的学习安排。
- [ ] 测验和闪卡完成后能改变知识点状态色,并反馈到库主页。
- [ ] 空库和 demo 库能让用户理解"脉络会长大"。
- [ ] `corepack pnpm run check` 通过。

产品成功:

- [ ] 用户首课后愿意回看总结。
- [ ] 用户首课后 24 小时内愿意进入库主页或做测验。
- [ ] 用户第二次课后能感知"它记得我上次的问题 / 这门课的暗线"。
- [ ] 用户完成一次今日学习后,能理解状态色为什么变化。

协作成功:

- [ ] 每次只实现一个任务组,不一口气做完整应用。
- [ ] Codex 和 Claude 不同时编辑同一文件组。
- [ ] 每个任务组完成后由另一个模型家族交叉审阅。
- [ ] 重要决策写回 `docs/ai/session-notes.md` 或执行包。

- 已有 docs 多数是未提交或已修改状态;执行时必须先读当前文件,不要回滚。

## 验收闸门

每个阶段完成后必须停下:

1. 运行最窄可用检查,默认 `corepack pnpm run check`。
2. 在微信开发者工具中按本阶段路径走查。
3. 说明真机检查项;录音相关阶段必须真机验证。
4. 由另一个模型家族做 code review。
5. 用户确认继续后,再进入下一阶段。
