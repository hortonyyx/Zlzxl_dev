# 需求 · 上课模式最小闭环 MVP

> 本总控执行包已按 2026-05-20 新决策调整。当前 MVP 不再以
> “学习脉络 + 今日学习 + 长期复习回写”为第一阶段目标，而是先把
> **一节节上课** 的真实链路跑通。

## 目标

第一版 MVP 要先验证一个更窄、更硬的课程学习闭环：

```text
创建课程学习库 → 开始上课 → 录音(先支持 10 分钟) → 上传录音 →
ASR 转写 → LLM 生成课堂输出 → 生成课后测验 → 用户文字 / 语音答题 →
LLM 点评 / 判分 → 回到本节课结果
```

核心目标是让用户在真实上完一节课后，立刻得到可用的课堂整理与测验。
学习脉络、今日学习、跨课复习调度先不作为本轮验收条件。

## 当前 MVP 范围

包含：

- 微信原生小程序 + TypeScript。
- 课程学习库：库列表、新建库、空库页、课程记录列表。
- 新建库：仅课程学习 + 库名；资料上传暂不做。
- 上课录音：先支持前台单次录音，最长 10 分钟。
- 录音上传：上传到微信云存储，得到 `fileID`。
- 课后处理：ASR 转写、LLM 生成课堂输出、LLM 生成测验题。
- 课堂输出：完整总结、要点提炼、核心问题、完整转写入口。
- 测验模块：只做问答题；支持文字答题与语音答题。
- 测验反馈：LLM 对答案做点评 / 判分。
- 服务层保留 mock / cloud 开关，云服务未配置时仍可走开发兜底。

暂不包含：

- 学习脉络重写、站点状态色、掌握信号回写。
- 今日学习、到期清单、AI 编排学习节点。
- 闪卡、语音抽背、听写。
- 完整 SRS / FSRS。
- 自主学习库完整体验。
- 课程资料上传。
- 45 分钟长录音、复杂分段续录、后台录音。
- 上线级合规、删除数据入口、账号体系。
- MVP 验证前的 Taro / uni-app / React / Vue 等跨端框架。

## 本轮页面范围

以 `docs/product/prototype.html` 为视觉事实来源，本轮实现 / 调整：

- 1 `library-list`：库列表 / 首页。
- 2 `library-create`：新建学习库；先隐藏或置灰资料上传。
- 3 `library-detail` 空库态：还没有上课记录，CTA 为“上第一节课”。
- 4 `library-detail` 有课态：课程记录列表 + “开始上课”；不做今日学习卡和学习脉络。
- 5 `station-detail`：改为单节课详情，展示本节课输出、转写入口、测验状态。
- 6 `class-record`：10 分钟录音页。
- 7 `class-processing`：转写 / 总结 / 生成测验进度。
- 8 `node-summary`：课堂总结节点。
- 10 `quiz-run`：问答测验，支持文字和语音答题。

暂不实现：

- 9 `study-node`。
- 11 `flashcard-run`。
- 12 `node-result` 作为“脉络更新结果页”的语义；后续可改为测验完成页。

## 第一版成功标准

功能成功：

- [ ] 可在微信开发者工具打开项目，并走通课程学习主路径。
- [ ] 可新建课程学习库，不需要上传资料。
- [ ] 可录制一段最长 10 分钟的课堂音频。
- [ ] 录音能上传到云存储，并关联到一节课。
- [ ] 课后处理能得到转写文本。
- [ ] 能生成三段式课堂输出：完整总结、要点提炼、核心问题。
- [ ] 能生成至少 3 道课后问答题。
- [ ] 用户能用文字答题并得到点评 / 判分。
- [ ] 用户能用语音答题：短录音 → 转写 → 点评 / 判分。
- [ ] `corepack pnpm run check` 通过。

产品成功：

- [ ] 用户完成一节课后愿意回看课堂输出。
- [ ] 用户能理解“开始测验”是在检验本节课。
- [ ] 语音答题不阻断流程；失败时可切文字答题。
- [ ] 10 分钟录音足以完成一次 MVP 试用验证。

协作成功：

- [ ] 每次只实现一个任务组。
- [ ] 页面仍只负责渲染、交互和生命周期。
- [ ] API / 云函数边界有明确 TypeScript 类型。
- [ ] 密钥只放云函数环境变量，不进入小程序代码。
- [ ] 每个任务组完成后由另一个模型家族交叉审阅。

## 待用户提供 / 决策

- 微信云开发环境 ID，以及是否允许本轮修改云开发相关配置。
- ASR 服务商与凭据配置方式。
- LLM 服务商、模型名、API Key / base URL 配置方式。
- 课堂录音格式要求：以微信录音可产出的格式和 ASR 服务兼容性为准。
- 一段 2-10 分钟真实课堂音频或现场录音测试材料。

## 验收闸门

每个阶段完成后必须停下：

1. 运行最窄可用检查，默认 `corepack pnpm run check`。
2. 在微信开发者工具中按本阶段路径走查。
3. 录音 / 语音答题相关阶段列出真机检查项。
4. 由另一个模型家族做 code review。
5. 用户确认继续后，再进入下一阶段。
