# 需求 · MVP（上课模式 + 学习模式）

> 功能级执行包。事实来源:[concept.md](../../product/concept.md)、
> [architecture.md](../../product/architecture.md)、
> [prototype.html](../../product/prototype.html)。
> 执行包目录沿用 `class-mode` 名,实际覆盖**上课 + 学习两个模式**。

## 目标

打通"输入 → 沉淀 → 复习"的完整学习循环,验证 Zlzl 的核心假设:
结构化的陪伴能带来复用与留存,而裸用通用大模型不能。

- 上课模式 = 知识点的输入泵。
- 学习模式 = 知识点的复习循环(护城河所在)。

两个模式是一个循环的两半,缺一不可。

## 用户

大学生。首批课型锁定**概念密集、叙述型、考试以理解与论述为主的大学课程**
(设计史、历史、文科理论课);数学 / 编程 / 物理等强练习课不进首批。
MVP 定位**纯个人学习用途**。

## 用户故事

- 作为大学生,我希望上课录音并课后自动转写、整理,以便不靠零散笔记。
- 作为大学生,我希望课后立即拿到结构化课堂总结(完整总结 + 要点提炼 +
  核心问题),以便快速掌握本节内容。
- 作为大学生,我希望进库时 AI 告诉我"今天该复习什么",以便不用自己规划。
- 作为大学生,我希望做 AI 编排的复习(测验 / 闪卡),以便巩固而非只看笔记。
- 作为长期用户,我希望每门课有一条随课次生长的学习脉络,以便看到学习
  轨迹和待解决的疑问。
- 作为用户,我希望 AI 记得我之前的疑问并在新课 / 复习里关联,以便感到
  被"记住"。

## 范围

本次包含:

- **库管理**:库列表;新建学习库——选学习方式(课程学习 / 自主学习,
  MVP 专注课程学习)+ 库名 + 多模态输入(上传文档 / 图片 / 拍照 / 文本);
  新建后进入空白库页(冷启动引导)。
- **上课模式**:课堂录音(前台连续 + 分段保存)、课后转写、课中标记疑问、
  上传课件 / 图片。
- **课堂总结**:课后生成固定三段式(完整总结 + 要点提炼 + 核心问题),
  立即固化。
- **知识点池**:知识点为一等实体,稳定 ID,归一化匹配,轻量 `relatedIds`。
- **学习模式**:进库出"今日到期清单";AI 编排学习节点(展示排了哪些点、
  为什么);节点内做模块;复习回写信号。
- **模块**:测验(支持语音作答与文字作答)、闪卡;两模式共用。
- **掌握状态**:简单到期规则(黄即时 / 绿固定 N 天 / 灰不计),
  信号按知识点 ID 时间序存储。
- **学习脉络**:逐课迭代,三层呈现(生长路径 / 单站详情 / 完整文档),
  delta 提示。
- 记录类产物的轻量纠错入口。
- 冷启动:预置只读 demo 示例库;空库引导"脉络会长大"。

本次不包含:

- 规划模式(显式目标 + 时间表)。
- 完整 SRS / FSRS 遗忘曲线。
- 测验 / 闪卡以外的模块(语音抽背、听写)。
- 知识点带类型双链与图感知编排。
- 用户在脉络上主动触发模块的入口。
- 自主学习库的完整体验(新建库可选"自主学习",但其交互待重新设计)。
- 语音轻输出;强练习课型;K12;跨平台框架。
- 轻量合规(录音前提示、删除入口)——已记录,MVP 暂不实现。

## 已决策(技术口径,实现须遵循)

- 后端:微信云开发(云函数 + 云数据库 + 云存储)。
- 登录:云开发 openid,不做账号体系。
- 密钥:LLM / ASR 密钥仅存云函数环境变量,不进小程序代码。
- 转写时机:课后转写;录音页极简,不在课中推送转写流。
- 算法:MVP 用简单到期规则;完整 SRS 为 v2。
- 验证策略:先 mock 工程(录音 / ASR / 云流水线),跑通体验闭环再硬化。

## 功能验收标准

上课线:

- [ ] 能新建库并完成多模态输入(库名 + 至少一类资料上传)。
- [ ] 能在上课模式**前台连续**录音整节课(≥45 分钟),录音分段保存。
- [ ] 切后台 / 锁屏 / 来电中断时,**已保存分段不丢**,并明确提示续录 /
      课后补录(不暗含后台继续录音)。
- [ ] 录音结束后能得到课后转写。
- [ ] 课中能标记疑问,标记课后归入脉络"还没解决的"。
- [ ] 课后自动生成固定三段式课堂总结并固化。
- [ ] 知识点入池;同一知识点跨课次出现时归一化复用 ID,不产生重复站点。

学习线:

- [ ] 进库能看到"今日学习"(到期清单)入口。
- [ ] AI 编排的学习节点能展示"排了哪些知识点、为什么"。
- [ ] 学习节点内能完成测验与闪卡。
- [ ] 复习结果回写为掌握信号,知识点状态色相应更新。

共享:

- [ ] 学习脉络三层可用;每次课后重写叙述,知识点 ID 与历史信号不受影响。
- [ ] 对课堂总结的错误能通过纠错入口反馈。
- [ ] `corepack pnpm run check` 通过。

## 记忆证据核心验收(护城河,弱则项目失败)

- [ ] 每次课后库主页有学伴口吻的「本次更新」delta。
- [ ] 学伴便签展示"还没解决的 / 我观察到的"。
- [ ] 新课总结 / 复习编排能体现**跨课关联**(如"上次 X 没解决,这次接上")。
- [ ] 第二次课后,用户能直观看到脉络可见地长大。

## 冷启动验收

- [ ] 零历史用户首次打开,有只读 demo 示例库,展示"3 次课后会变成什么样"。
- [ ] 空库不只显示"开始上课",而是传达"脉络会长大"。

## 产品验证指标（与功能验收分开,用于判断假设是否成立）

- 首课后:用户是否愿意保存 / 回看总结。
- 首课后 24 小时内:是否打开脉络或做测验。
- 第二次课后:是否感知到跨课记忆与 delta。
- 连续两次课后:是否主动回到库主页(而非只看总结节点)。
- 测验完成率:用户是否真的愿意答完题。
- 纠错率:AI 总结错误是否高到破坏信任。

> 这些指标不一定一开始自动埋点,但必须写入文档,避免用"功能跑通"
> 替代"假设被验证"。

## 边界场景

- 录音中断(切后台 / 锁屏 / 来电 / 内存不足)→ 已保存分段不丢,
  可续录或课后补录。
- 录音 / 转写 / LLM 失败、超时 → 明确失败提示与重试。
- 长音频文件过大上传失败 → 分段上传 / 重试。
- 首次使用、零历史 → demo 库 + 空状态引导。
- 同一知识点跨课次重复出现 → 归一化匹配,复用 ID。
- 转写质量差(口音、术语、噪音)→ 允许编辑 / 纠错。
- AI 总结出错 → 纠错入口。
- 学习模式无到期项(全绿且未到期)→ 给"暂无需复习"的正向空状态。
